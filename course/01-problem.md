# Как прочитать формулу предсказания текста

Начнём с действия: вы набираете «кот», а автодополнение предлагает «спит». Нам нужна программа, которая оценивает разные продолжения. Формула — короткая запись этого действия. Сначала назначим буквам смысл, а затем научимся читать запись целиком.

## Сначала пример без обозначений

Пусть игрушечный словарь состоит из токенов «кот», «спит» и «.». Токен — элемент, которым оперирует модель; здесь это слово или знак, а в лабораторной модели это будет символ. После слова «кот» программа выдаёт таблицу:

| Кандидат на продолжение | Вероятность |
| --- | --- |
| «кот» | 0,1 = 10% |
| «спит» | 0,6 = 60% |
| «.» | 0,3 = 30% |

Все числа неотрицательны и вместе дают 1, то есть 100%. Один вызов модели выдаёт такую таблицу, а программа генерации затем выбирает из неё токен.

## Маленькая v и большой словарь

Весь словарь обозначим каллиграфической буквой $\mathcal{V}$, а один выбранный токен из него — маленькой буквой $v$. Так удобно различать множество кандидатов и один его элемент. Для нашего примера:

```math
\mathcal{V}=\{\text{«кот»},\text{«спит»},\text{«.»}\},\qquad v\in\mathcal{V}
```

Читайте: «словарь состоит из этих трёх токенов; v — какой-нибудь токен из словаря». Знак $\in$ означает «принадлежит». Маленькая $v$ — как переменная `candidate` в цикле: подставляйте «кот», «спит» или «.».

Число элементов словаря обозначим $V=|\mathcal{V}|$. Здесь V=3. Черты вокруг множества означают его размер. В attention буква V позже обозначит матрицу значений: там будет отдельное определение. Смысл обозначения определяется в контексте формулы.

## p и вертикальная черта: что спрашиваем

```math
p(\text{«спит»}\mid\text{«кот»})=0{,}6
```

Читайте: «вероятность „спит“ при условии, что уже известен контекст „кот“, равна 0,6». Слева от $\mid$ — то, вероятность чего спрашиваем. Справа — уже известная информация. Черта здесь означает **«при условии»**.

В голове можно представлять вызов функции:

```python
probability(candidate="спит", context=["кот"])  # 0.6
```

Этот псевдокод показывает смысл вызова. Настоящая модель обычно возвращает сразу весь вектор вероятностей.

## x, i и t: токены и их номера

Для текста «кот спит .» договоримся:

| Запись | Смысл в примере | Аналог в программе |
| --- | --- | --- |
| $x$ | последовательность токенов | `tokens` |
| $x_1$ | первый токен, «кот» | `tokens[0]` |
| $x_2$ | второй токен, «спит» | `tokens[1]` |
| $x_3$ | третий токен, «.» | `tokens[2]` |
| $i$ | текущий номер при переборе: 1, 2, 3 | счётчик цикла |
| $t$ | число рассматриваемых токенов; здесь 3 | `len(tokens)` |

$x_i$ обозначает токен на позиции i. Здесь математика считает с 1, Python — с 0. Буквы выбраны по соглашению: i часто обозначает перебор, t — шаг последовательности. Можно выбрать другие буквы и явно их определить. В этом уроке t — длина рассматриваемого фрагмента; при генерации она растёт.

```math
p(x_{t+1}=v\mid x_1,\ldots,x_t)
```

Читайте по частям: «вероятность того, что **следующий** токен окажется **кандидатом v**, если известны **первые t токенов**». Многоточие заменяет перечисление промежуточных элементов. Для контекста «кот» t=1. Подставьте v=«спит» и получите уже знакомый вопрос с ответом 0,6.

## Произведение и сумма

Знак $\prod$ — большая греческая буква пи. Он означает **перемножить несколько значений**, аналог `math.prod`.

```math
\prod_{i=1}^{3}a_i=a_1\cdot a_2\cdot a_3
```

Снизу — с какого номера начать: i=1. Сверху — на каком закончить: 3. Справа — что брать на каждом шаге: элемент $a_i$. Мысленно подставляйте i=1, затем 2, затем 3 и перемножайте результаты.

Похожий знак $\sum$, большая сигма, означает **сложить**, аналог `sum`:

```math
\sum_{i=1}^{3}a_i=a_1+a_2+a_3
```

Счётчик внутри суммы или произведения локален, как переменная цикла. В другой формуле он может нумеровать другие объекты — это нужно определить перед формулой.

## Почему вероятности перемножаются

Чтобы получить целый текст, нужно пройти все шаги: выбрать «кот», затем «спит» после «кот», затем точку после «кот спит». Представляйте путь по дереву продолжений. Вероятность пути — произведение вероятностей переходов с учётом уже пройденной части.

```math
\begin{aligned}
p(\text{«кот спит .»})&=p(\text{«кот»})\cdot p(\text{«спит»}\mid\text{«кот»})\\
&\quad\cdot p(\text{«.»}\mid\text{«кот спит»})\\
&=0{,}2\cdot0{,}6\cdot0{,}5=0{,}06.
\end{aligned}
```

Представьте 1000 попыток: в среднем 200 начнутся с «кот», из них 120 продолжатся «спит», а 60 завершатся точкой. Это мысленный эксперимент с указанными вероятностями. Теперь тот же расчёт коротко:

```math
p(x_1,\ldots,x_t)=\prod_{i=1}^{t}p(x_i\mid x_1,\ldots,x_{i-1})
```

Читайте: «вероятность всей последовательности — произведение вероятностей каждого токена при известном префиксе перед ним». Для первого токена префикс пуст или содержит маркер начала. Независимость слов не требуется: зависимость как раз записана после условной черты.

## Почему именно логарифм

Обучение должно повышать вероятность настоящих продолжений. Можно максимизировать вероятность всей обучающей последовательности, но произведение длинной цепочки быстро становится крошечным. Удобнее перейти к сумме отдельных вкладов и сохранить предпочтение «большая вероятность лучше маленькой».

Натуральный логарифм $\ln p$ отвечает: **«в какую степень надо возвести e, чтобы получить p?»** Здесь $e\approx2{,}71828$. Например, $\ln1=0$, а $\ln(e^{-2})=-2$. Его ключевое свойство:

```math
\ln(a\cdot b)=\ln a+\ln b
```

Почему? Если $a=e^u$ и $b=e^w$, то $ab=e^{u+w}$. Логарифм возвращает показатель степени, поэтому у произведения получается u+w. Представляйте переход от **перемножения множителей** к **накоплению вкладов на другой шкале**.

Для нашей цепочки возьмём отрицательный логарифм:

```math
\begin{aligned}
-\ln(0{,}2\cdot0{,}6\cdot0{,}5)
&=-\ln0{,}2-\ln0{,}6-\ln0{,}5\\
&\approx1{,}609+0{,}511+0{,}693\\
&=2{,}813.
\end{aligned}
```

Произведение превратилось в сумму штрафов. Минус нужен, чтобы хорошему предсказанию соответствовала **маленькая** ошибка: её удобно минимизировать. Деление на число токенов даёт среднюю ошибку: 2,813 / 3 ≈ 0,938.

| Вероятность правильного токена p | Штраф $-\ln p$ | Смысл |
| --- | --- | --- |
| 1 | 0 | полная уверенность в правильном варианте |
| 0,9 | ≈ 0,105 | небольшой штраф |
| 0,5 | ≈ 0,693 | заметная неопределённость |
| 0,1 | ≈ 2,303 | реальный токен считался маловероятным |
| 0,01 | ≈ 4,605 | ещё больший штраф |

Каждое уменьшение p в 10 раз добавляет одинаковый штраф $\ln10\approx2{,}303$. Штраф принимает любые неотрицательные значения. Для p=0 конечного логарифма нет; штраф в пределе растёт без границы.

Логарифм выбран не только ради удобных чисел. Минимизация суммы отрицательных логарифмов эквивалентна максимизации вероятности наблюдённых данных — методу максимального правдоподобия. Такая цель поощряет согласованное распределение вероятностей и сильно штрафует уверенное исключение реального события. Другие функции потерь существуют, но задают другую цель. Для этой вероятностной постановки логарифм возникает естественно.

В программе важно вычислять устойчивые log-probabilities из logits, а не сначала получать очень маленькое произведение и только затем брать логарифм. Иначе произведение может округлиться до нуля раньше, чем вы примените логарифм. Позже разберём `log_softmax` и `cross_entropy`.

## θ, N и итоговая функция обучения

$\theta$ («тета») — короткое имя для **всех обучаемых весов**. Подпись в $p_\theta$ напоминает: вероятности вычисляет модель с этими весами. Скобки в $L(\theta)$ говорят, что ошибка зависит от весов.

Пусть N — количество учитываемых предсказаний, а $p_i$ — вероятность, которую модель назначила **правильному** токену в наблюдении i. Тогда:

```math
L(\theta)=-\frac{1}{N}\sum_{i=1}^{N}\ln p_i
```

Прочтите как инструкцию: «для каждого правильного токена взять вероятность, посчитать отрицательный логарифм, сложить штрафы и разделить на их количество». N может быть числом токенов в целом пакете; оно не обязано совпадать с длиной t одной строки. Обучение меняет θ, чтобы уменьшить это среднее.

## Обучение и использование

При обучении правильное продолжение известно. Позиции строки можно обрабатывать одновременно, скрыв от каждой будущие токены маской. Это teacher forcing. При обычной генерации продолжение неизвестно: выбрали токен, добавили в контекст, вызвали модель снова. Веса θ при этом обычно не обновляются.

Предсказание текста не гарантирует истинность ответа. Контекст влияет на текущее вычисление, а не автоматически переписывает веса. Сейчас важно понимать задачу; механизм расчёта вероятностей построим в следующих модулях.

## Проверьте, что запись стала читаемой

1. В формулу следующего токена подставьте t=2, контекст «кот спит», v=«.». Прочитайте вопрос словами.
2. Раскройте $\prod_{i=1}^{3}p_i$ и $\sum_{i=1}^{3}(-\ln p_i)$ без знаков произведения и суммы.
3. Если вероятность каждого из трёх правильных токенов равна 0,5, найдите вероятность цепочки и среднюю ошибку.
4. Почему сумма логарифмов равна логарифму произведения, но для программы предпочтительнее первый путь?

<p>1. «Какова вероятность точки после известных „кот спит“?» 2. p₁ × p₂ × p₃; (−ln p₁) + (−ln p₂) + (−ln p₃). 3. Вероятность 0,125; полный штраф ≈ 2,079; средний ≈ 0,693. 4. Равенство следует из свойства логарифма.
