# Обучение — управляемый эксперимент

На каждом шаге берём пакет примеров, вычисляем logits, ошибку, градиенты и обновляем параметры. Размер пакета B определяет, сколько примеров участвует в одной оценке градиента. Стохастический градиент — приближение градиента по всем данным, поэтому ошибка отдельного шага может колебаться.

```python
model.train()
optimizer.zero_grad(set_to_none=True)
logits, loss = model(inputs, targets)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()
```

Обнуление нужно до обратного прохода независимого шага. `clip_grad_norm_` ограничивает общую норму градиента; это страховка от слишком больших обновлений, а не исправление неправильных данных или формул. Считать градиенты ещё не значит обновить веса: обновление выполняет `optimizer.step()`.

## SGD и Adam

Простейший SGD: θ←θ−ηg. Adam хранит экспоненциальные средние градиента m и его квадрата v:

```text
mₜ = β₁mₜ₋₁ + (1−β₁)gₜ
vₜ = β₂vₜ₋₁ + (1−β₂)gₜ²          квадрат покоординатный
m̂ₜ = mₜ/(1−β₁ᵗ),  v̂ₜ = vₜ/(1−β₂ᵗ)
θₜ = θₜ₋₁ − η m̂ₜ/(sqrt(v̂ₜ)+ε)
```

Коррекция смещения нужна потому, что m₀=v₀=0. Нормирование по масштабу градиентов помогает разным координатам делать разные эффективные шаги. Adam не гарантирует глобальный минимум нейросети.

AdamW отдельно уменьшает веса: добавляет обновление −ηλθ. Это weight decay. В нашей простой реализации учебный оптимизатор применяется одинаково ко всем параметрам; в больших проектах параметры часто разбивают на группы, исключая bias и нормировки из decay.

## Обучающая и проверочная выборки

Train используется для градиентов. Validation — для выбора решений и ранней диагностики. Test — для окончательной независимой оценки, которую нельзя многократно использовать для настройки. Если по test принимаются инженерные решения, он фактически стал validation.

Разделяйте текст до нарезки перекрывающихся окон. Иначе почти одинаковые фрагменты могут попасть в разные части. Для реального корпуса нужны также дедупликация, учёт общих источников, авторов и времени. Низкая validation loss на искусственном повторяющемся корпусе не доказывает понимание языка.

Признаки переобучения: train loss падает, validation loss устойчиво растёт. Возможные действия: больше подходящих данных, меньше модель, регуляризация, остановка раньше. Если обе ошибки не падают, проверьте сдвиг целей, маску, learning rate, обучение параметров и корректность самой задачи.

## План отладки

Сначала добейтесь переобучения на одном маленьком пакете: исправная модель должна уметь запомнить его. Потом проверьте разделение данных и обучение на полном корпусе. Меняйте один фактор за эксперимент и фиксируйте seed, конфигурацию, версии и метрики. Seed уменьшает случайность, но не гарантирует побитовую воспроизводимость на другом устройстве.

## Задача

Почему после двух вызовов `backward()` без `zero_grad()` второй градиент не соответствует только второму пакету? Как корректно накапливать градиент за четыре микропакета одинакового размера?

<details><summary>Ответ</summary>
<p>В .grad складываются вклады. Для эффективного среднего по четырём микропакетам обнулите градиенты один раз, для каждого вычислите (loss/4).backward(), затем один раз выполните clip и step. При разных размерах нужно взвешивать по числу учитываемых токенов.</p>
</details>

Критерий готовности: вы различаете ошибку обучения, validation и тест, и можете назвать проверку для каждого подозрительного симптома.
