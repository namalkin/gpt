# Python и тензоры

В практикуме Python служит записью математики. Первые примеры языка можно выполнить без PyTorch: запустите `docker compose run --rm scratch python` и вводите их по строкам. Для раздела о тензорах понадобится среда `lab` с PyTorch. Ниже разберём, зачем она нужна и какие части можно написать самостоятельно.

```python
numbers = [2, 4, 6]           # список
total = sum(numbers)         # сумма, 12
for value in numbers:        # цикл; отступ — часть синтаксиса
    print(value * 2)

def square(x):               # определение функции
    return x * x

print(square(3))             # вызов функции, 9
```

`=` присваивает значение, `==` сравнивает, `*` умножает, `**` возводит в степень. Индексы начинаются с нуля. Срез `numbers[1:]` даёт `[4,6]`. Функция получает аргументы и возвращает результат; переменная — имя, связанное с объектом. Комментарии после `#` не исполняются.

## Почему используем PyTorch и можно ли обойтись без него

Обойтись можно. Трансформер — математическая конструкция; PyTorch — один из инструментов её реализации. Для нашей версии `labs/model.py` библиотека нужна, потому что исходник вызывает её API. Из самой математики обязательность именно этой библиотеки не следует.

Полезно разделить три уровня:

| Уровень | Что нужно реализовать | Кто делает это в практикуме |
| --- | --- | --- |
| Алгоритм модели | представления, Q/K/V, маска, attention, блоки, ошибка и цикл обучения | мы задаём структуру в `labs/model.py` и `labs/experiments.py` |
| Автоматическое дифференцирование | проследить зависимости и применить цепное правило ко всем параметрам | PyTorch autograd; маленький пример ниже считает градиенты вручную |
| Численный движок | хранение массивов, матричные операции, управление памятью, использование CPU/GPU | PyTorch и подключённые низкоуровневые реализации |

«Написать свой алгоритм» может означать работу на любом из этих уровней. Можно придумать новую архитектуру на готовом численном движке. Можно реализовать свой движок и оставить архитектуру прежней. Можно написать и то и другое — объём работы будет значительно больше.

Формула матричного произведения определяет результат вычисления. Численная библиотека предоставляет готовую реализацию этой операции. В практикуме мы разбираем формулы и явно задаём структуру модели, а библиотеке поручаем повторяющиеся численные вычисления.

### Как считали раньше

Нейросети не появились вместе с PyTorch. Прямой проход, производные и обновление весов можно программировать вручную. Для линейной алгебры давно существуют готовые наборы процедур, например [BLAS](https://netlib.org/blas/): операции над векторами и матрицами. Оптимизированная реализация умножения матриц — самостоятельная инженерная работа.

До PyTorch были и другие системы вычислений. Например, [отчёт Theano 2016 года](https://arxiv.org/abs/1605.02688) описывает вычисления над массивами на CPU/GPU и сравнивает систему с Torch7 и TensorFlow. История инструментов включает ручные реализации, численные библиотеки, системы автоматического дифференцирования и фреймворки.

### Что именно экономит библиотека

Матричное произведение можно написать тремя циклами. Но для высокой производительности приходится учитывать расположение данных, кеш процессора, векторные инструкции, многопоточность, передачу данных и особенности ускорителя. На большом количестве элементов накладные расходы интерпретатора Python тоже заметны. Готовые тензорные операции выполняют основную работу в низкоуровневом коде; вызов Python задаёт операцию, а не исполняет каждый её элемент отдельной Python-инструкцией.

Отдельная экономия — градиенты. Для маленькой функции их удобно вывести и написать руками. В глубокой модели нужно корректно собрать тысячи локальных зависимостей, суммировать вклады повторно используемых весов и сохранить нужные промежуточные значения. Autograd автоматизирует применение цепного правила к выполненному графу. Производные вычисляются по правилам дифференцирования с обычной погрешностью численной арифметики. Подробнее: [документация autograd](https://docs.pytorch.org/docs/stable/notes/autograd.html).

PyTorch не выбирает за нас задачу, корпус, маску, конфигурацию и критерий проверки. Неправильную модель он тоже способен быстро и последовательно вычислять. Поэтому нужны ручные выводы, численные примеры и тесты.

### Сначала попробуем без PyTorch

В репозитории есть `labs/from_scratch.py`. Он использует только стандартную библиотеку Python: `math`, списки и циклы. Отдельный контейнер не устанавливает PyTorch или NumPy:

```powershell
docker compose run --rm scratch
docker compose run --rm scratch python -m unittest labs.test_from_scratch -v
```

Первый запуск скачает обычный образ Python, если его ещё нет. Программа повторяет численный causal attention из курса, затем обучает маленькую линейную модель для одного фиксированного контекста. Вы вручную задаёте два искусственных признака контекста и хотите получить распределение продолжений «кот», «спит», «.» с частотами 0,1; 0,6; 0,3.

Сначала logits вычисляются явными суммами произведений. Затем выполняются softmax и cross-entropy. Производная по logits записана руками как p−q, производная по весу — как входной признак, умноженный на p−q. Наконец обычные циклы выполняют шаг градиентного спуска. После обучения вероятности приближаются к заданным частотам. Градиент отдельно проверяется центральной разностью.

Это две маленькие демонстрации: обучаемый классификатор не содержит attention и не является GPT. Они показывают, что и attention, и обучение не зависят от наличия фреймворка. Ошибка классификатора не обязана стать нулевой: целевое распределение допускает три разных продолжения, и его собственная энтропия положительна.

### Почему дальше возвращаемся к PyTorch

Для учебного скаляра и маленькой матрицы ручная реализация особенно полезна. Для нескольких блоков трансформера готовый движок позволяет сосредоточиться на устройстве модели, отладке и экспериментах. В этом курсе используем такой маршрут: **вывести формулу → посчитать руками → реализовать маленький пример → перенести в тензорные операции → проверить совпадение**.

Вы можете продолжить путь без фреймворка: добавить к чистому Python обучаемые embeddings, полный обратный проход attention, MLP и нормировки. Это отдельный содержательный проект. Следующий уровень — реализовать собственное автоматическое дифференцирование; ещё один — оптимизировать численные ядра. Знание PyTorch само по себе не заменяет ни один из этих уровней понимания.

## Скаляр, вектор, матрица, тензор

Скаляр — одно число. Вектор — упорядоченный набор чисел. Матрица — таблица. Тензором в программировании называют массив с любым количеством осей. Ось — отдельное измерение, shape — размеры всех осей, dtype — тип элементов. С этого места откройте Python в основной среде: `docker compose run --rm lab python`; в контейнере scratch библиотека torch отсутствует.

```python
import torch
x = torch.tensor([[1., 2., 3.], [4., 5., 6.]])
print(x.shape)               # torch.Size([2, 3])
print(x[0, 1])               # 2
print(x.sum(dim=-1))         # [6, 15], суммируем последнюю ось
print(x.mean())              # 3.5
print(x.T.shape)             # [3, 2]
```

Точка после числа создаёт вещественное значение. Веса обычно вещественные; индексы токенов целые, типа `torch.long`. Три оси `[B,T,D]` означают B примеров, T позиций в каждом, D признаков позиции. Это соглашение нужно помнить, иначе код с допустимыми формами может считать не то.

## Два разных умножения

`x * y` перемножает соответствующие элементы. `x @ y` выполняет матричное произведение. Для `[B,T,D] @ [D,K]` получаем `[B,T,K]`: одна матрица применяется к каждой позиции каждого примера.

```python
w = torch.ones(3, 2)
print((x @ w).shape)         # [2, 2]
print(x + torch.tensor([10., 20., 30.]))
```

Последняя операция использует broadcasting: вектор длины 3 прибавляется к каждой строке. Оси сравниваются справа; размеры должны совпадать или один из них должен быть 1. Broadcasting не копирует математический смысл: случайно совместимые оси легко скрывают ошибку.

`reshape` меняет форму при сохранении числа элементов; `transpose` меняет местами оси. Это разные действия. Для внимания `[B,T,H×d]` превращают в `[B,T,H,d]`, затем переставляют в `[B,H,T,d]`. Именно перестановка собирает позиции одной головы вместе.

## Первое упражнение

Создайте `a = torch.arange(24).reshape(2,3,4)`. Предскажите `a[1,0,2]`, форму `a.mean(dim=1, dtype=torch.float32)` и форму `a.transpose(1,2)` до выполнения.

<details><summary>Ответ</summary>
<p>14; [2,4]; [2,4,3]. Первая половина содержит числа 0…11, вторая — 12…23. После усреднения исчезает ось длины 3. Перестановка не меняет значения, но меняет их координаты.</p>
</details>
