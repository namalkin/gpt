# Как модель использует выученные веса

Генерация начинается с prompt: кодируем его тем же словарём, вычисляем logits и берём распределение только последней позиции. Выбираем следующий токен, добавляем его к входу и повторяем. В учебной модели нет специального EOS, поэтому генерация останавливается по заданному числу токенов.

## Способы выбора

Greedy выбирает argmax. Sampling случайно выбирает токен с заданными вероятностями. Temperature τ>0 меняет распределение:

```math
p_i(\tau)=\operatorname{softmax}(z/\tau)_i,\qquad\tau>0
```

При τ<1 распределение обычно становится резче, при τ>1 — более плоским.

Temperature не проверяет факты и не добавляет знания. При τ→0 выбор приближается к максимуму, но вычислять деление на ноль нельзя. Top-k оставляет k крупнейших logits и нормирует оставшиеся. Top-p оставляет минимальный префикс отсортированных токенов, чья суммарная вероятность достигает p. В лаборатории реализованы temperature и top-k.

```powershell
docker compose run --rm lab python -m labs.experiments generate --prompt "текст " --temperature 0.7 --top-k 10 --tokens 160
```

Неизвестные символы prompt кодируются `<unk>` с предупреждением. Сам `<unk>` не выбирается при генерации. Если результат беден или повторяется, причина может быть в маленьких данных и модели, а не только в параметре temperature.

## Prefill и decode

Prefill обрабатывает известный prompt. Его позиции можно вычислять параллельно внутри слоя. Decode добавляет новые токены. При обычной авторегрессии токен t+1 зависит от выбранного t, поэтому последовательность новых токенов нельзя просто сгенерировать одним независимым вызовом. Между шагами сохраняется зависимость, даже если каждый шаг массивно параллелен внутри.

## KV cache

Для старых позиций K и V каждого слоя уже вычислены. При причинной модели новые токены не могут изменить старые состояния. Значит, их можно сохранить, а для нового токена вычислять только новый Q,K,V. Новый Q сравнивается со всеми сохранёнными ключами.

```text
Без кеша: на каждом шаге пересчитываем весь известный префикс.
С кешем: сохраняем K,V по слоям; добавляем по одной позиции.
Размер кеша в байтах ≈ 2 L B T H_kv d × bytes_per_element.
```

Для обычного MHA H_kv=H, Hd=D, значит размер 2LBTD×bytes. При L=24,B=1,T=4096,D=2048 и BF16 по 2 байта это 805 306 368 байт, то есть 768 MiB. Это только кеш, без весов, временных буферов и overhead.

GQA использует меньше групп K,V, чем голов Q, уменьшая кеш. В MQA все головы запросов делят одну голову K,V. Часть гибкости обменивается на память и пропускную способность; качество и скорость нужно измерять.

В нашей реализации кеша нет: для прозрачности она каждый раз пересчитывает обрезанный контекст. Добавить простой кеш при сдвигаемых обучаемых позициях нельзя бездумно: когда окно обрезается и позиции перенумеровываются, старые K,V уже соответствуют другим позиционным входам.

## Задача

Почему `model.eval()` недостаточно для экономии памяти автодифференцирования? И почему KV cache не заменяет веса модели?

<details><summary>Ответ</summary>
<p>eval меняет поведение отдельных слоёв, но не отключает autograd; нужен no_grad или inference_mode. Кеш — временные представления конкретного контекста, вычисленные при помощи весов. Для другого запроса он обычно другой.</p>
</details>
