# Полная языковая модель

Соберём цепочку, которая из целых индексов получает вероятность следующего токена:

```text
ids [B,T]
    → token embedding + position embedding [B,T,D]
    → L блоков трансформера                [B,T,D]
    → финальная LayerNorm                 [B,T,D]
    → линейная проекция в словарь          [B,T,V]
    → cross-entropy с targets [B,T]
```

Скрытый вектор позиции t содержит информацию только об x₁…xₜ. Его logits сравниваются с xₜ₊₁. Внутри `cross_entropy` оси B,T временно объединяются: logits становятся [B×T,V], targets — [B×T]. По умолчанию считается средняя ошибка по B×T токенам.

## Конкретная конфигурация

Учебный GPT: D=64,H=4,L=2,T_max=64,F=4D=256. Входное embedding и выходная матрица раздельны. QKV, выход attention, MLP и lm_head не имеют bias. Каждая LayerNorm имеет γ и β. Это важно для точного подсчёта.

```math
\begin{aligned}
N_{\text{token}}&=VD,&N_{\text{position}}&=T_{\max}D\\
N_{\text{attention}}&=4D^2,&N_{\text{MLP}}&=8D^2\\
N_{\text{norm/block}}&=4D,&N_{\text{final norm}}&=2D\\
N_{\text{output}}&=DV\\[4pt]
N&=2VD+T_{\max}D\\
&\quad+L(12D^2+4D)+2D
\end{aligned}
```

При V=100 получаем 12 800+4096+2×49 408+128=115 840 параметров. Реальное V определяется корпусом, поэтому программа печатает точное число. Разбиение на головы при фиксированном D число параметров этих матриц не меняет.

## Где находится обучение

Каждый embedding и каждая матрица блока — часть θ. На входе индексы выбирают строки, attention вычисляет связи, MLP меняет признаки, финальная проекция выдаёт logits. Ошибка одного следующего токена даёт градиент всем параметрам, которые влияли на его распределение. Ранние позиции участвуют в предсказании множества последующих токенов и получают несколько вкладов.

Не существует отдельного вручную написанного правила «если местоимение, найди существительное». Архитектура предоставляет средства сопоставления, а обучение подбирает численные преобразования. Если задача и данные не поощряют нужную закономерность, она может не сформироваться.

## Чтение реализации

Откройте `labs/model.py`. Прочитайте классы в порядке `GPTConfig`, `CausalSelfAttention`, `Block`, `TinyGPT`. Проследите каждую строку `forward` и подпишите формы. Проверьте, что mask зарегистрирована как buffer: она перемещается с моделью, но не является обучаемым параметром.

В нашей реализации scores явно материализуются как [B,H,T,T]. Это удобно для обучения человека и не оптимально для больших контекстов. В производственном коде часто используют fused scaled dot product attention, который может выбрать более эффективное ядро.

## Задачи

1. Как изменится число параметров при удвоении T_max? При удвоении D с тем же L?
2. Почему увеличение batch size не увеличивает файл весов?
3. Что нужно сохранить кроме `state_dict`, чтобы потом декодировать результат?

<details><summary>Ответ</summary>
<p>1. Добавится T_max D позиционных параметров; основные матрицы при удвоении D вырастут в четыре раза, embeddings — вдвое. 2. Веса переиспользуются для всех примеров. 3. Конфигурацию архитектуры и тот же токенизатор/словарь; для продолжения обучения также состояние оптимизатора, шаг и состояния генераторов случайности.</p>
</details>
